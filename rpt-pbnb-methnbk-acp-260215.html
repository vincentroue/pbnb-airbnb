Justification des choix

AstuceDécisions clés

Prix null = inactif : 80,8 % des listings à prix null ont availability_365 = 0. Ce sont des annonces retirées ou dormantes, pas des erreurs de saisie. Seulement 1,2 % d’anomalies (prix null mais listing actif).

Hotel room exclu : Représente ~1 % de la base. Comportement tarifaire et d’usage très différent (réservation plateforme hôtelière, pas location de logement).

Prix [10, 1000] EUR : Borne basse (10€/nuit) exclut les erreurs de saisie. Borne haute (1000€) : au-delà, marché de niche ultra-luxe non représentatif.

Longterm flaggé, pas exclu : minimum_nights ≥ 30 est un indicateur de régulation (effet Barcelona, Berlin, Istanbul). Exclure ces listings masquerait un signal structurel majeur.

Protocole

  1. Standardisation : centrage-réduction (z-scores) sur les 12 variables actives
  2. ACP : décomposition en valeurs propres de la matrice de corrélation
  3. Rétention : composantes retenues selon règle des 80 % de variance cumulée
  4. Clustering Ward : distance euclidienne sur les 4 premières composantes
  5. Choix de k : score silhouette pour k ∈ {3, 4, 5, 6}, retenir le maximum
  6. Profils : médiane par cluster sur les variables clés
AstucePourquoi Ward sur composantes et pas sur variables brutes ?

Les variables ont des échelles très différentes (pression 0-55, prix 37-223, pct 0-98). La standardisation résout ce problème, mais l’ACP apporte en plus : - Décorrélation : les composantes sont orthogonales → distance euclidienne cohérente - Réduction de bruit : les dernières composantes captent du bruit, pas du signal - Interprétabilité : les clusters se projettent lisiblement sur le biplot

  1. Snapshot unique (juin 2025) : pas de dimension temporelle, saisonnalité masquée

## Étapes détaillées

### Étape 1 — Download (`sp04`)

**Source** : [Inside Airbnb](https://insideairbnb.com/get-the-data/) — données publiques compilées par Murray Cox.

| Type fichier | Colonnes | Usage | Taille/ville |
|:-------------|:---------|:------|:-------------|
| `listings.csv.gz` | 74 | Détail complet (amenities, descriptions, scores) | 5-50 MB |
| `listings.csv` (sumlistings) | 18 | Résumé léger (prix, dispo, reviews) | 0.5-3 MB |
| `neighbourhoods.geojson` | géométrie | Contours quartiers | 0.1-2 MB |
| `neighbourhoods.csv` | 2 | Liste quartiers | < 10 KB |

**Paramétrage** : Filtrage par continent (`-e` Europe), pays (`-c france`), types de fichiers (`-l -s -g -n`). Retry 3× avec rate-limiting (1s entre requêtes).

**Organisation** :
```
data/raw/zudb-inside-airbnbbnb/
├── europe/{pays}/{ville}/{YYYY-MM-DD}/listings.csv.gz
├── usa/united-states/{ville}/...
└── world/{pays}/{ville}/...
```

### Étape 2 — Flatten (`sp06`)

Transformation de l'arborescence datée vers un nommage plat pour simplifier la consolidation :

```
Avant : europe/france/paris/2025-06-18/listings.csv.gz
Après : europe/france/paris/25-06/
        + 25-06-FRA-paris_sumlistings.csv
        + geo-FRA-paris_neighbourhoods.geojson
```

### Étape 3 — Consolidation (`sp07`)

- **Scan** des 3 dossiers racines (`europe/`, `usa/`, `world/`)
- **Exclusion des régions** : Sicile, Crète, Baléares, Pays Basque, Basilicate... (biais rural)
- **Seuil** : minimum 3 000 listings par ville (exclut villes trop petites)
- **Enrichissement** : ajout `country_code`, `continent`, `city_pop`, `city_housing`, `city_lat`, `city_lon`
- **Conversion FX** : 21 devises non-EUR converties via taux BCE (février 2026)

**Référentiel population** (`city_reference_data.py`) :
- 35 villes Europe avec données **commune propre** (pas métropole)
- Sources : INSEE (FR), ISTAT (IT), ONS (UK), INE (ES), Eurostat...
- Logements : recensement officiel ou estimation par ratio national (OCDE)

### Étape 4 — Calcul KPIs (`sp08`)

Le script applique le **pipeline de nettoyage** (voir section suivante), puis calcule 25 indicateurs par ville regroupés en 7 catégories.

# Pipeline de nettoyage

```{python}
#| label: cleaning-pipeline

df_raw = pd.read_parquet(BASE / "data" / "interim" / "dbsumlistings_2506_cons_global.parquet")
n_raw = len(df_raw)

steps = []
df_c = df_raw.copy()

# Étape 1 : Prix non null
mask = df_c["price"].notna() & (df_c["price"] > 0)
steps.append(("1. Prix non null (exclure inactifs)", mask.sum(), len(df_c) - mask.sum()))
df_c = df_c[mask]

# Étape 2 : Disponibilité > 0
mask = df_c["availability_365"] > 0
steps.append(("2. Disponibilité > 0 jours/an", mask.sum(), len(df_c) - mask.sum()))
df_c = df_c[mask]

# Étape 3 : Exclure Hotel room
mask = df_c["room_type"] != "Hotel room"
steps.append(("3. Exclure Hotel room", mask.sum(), len(df_c) - mask.sum()))
df_c = df_c[mask]

# Étape 4 : Prix EUR 10-1000 (aberrants)
if "price_eur" in df_c.columns:
    mask = (df_c["price_eur"] >= 10) & (df_c["price_eur"] <= 1000)
    steps.append(("4. Prix EUR [10, 1000] (aberrants)", mask.sum(), len(df_c) - mask.sum()))
    df_c = df_c[mask]

# Étape 5 : Flag longterm (PAS d'exclusion)
if "minimum_nights" in df_c.columns:
    n_lt = (df_c["minimum_nights"] >= 30).sum()
    steps.append((f"5. Flag is_longterm (≥30 nuits) — NON exclu", len(df_c), 0))

print(f"Pipeline de nettoyage — Impact sur {n_raw:,} listings bruts\n")
print(f"{'Étape':<45s} {'Restant':>10s} {'Exclu':>10s} {'% brut':>8s}")
print("─" * 75)
cumul_exclu = 0
for name, kept, removed in steps:
    cumul_exclu += removed
    print(f"{name:<45s} {kept:>10,} {removed:>10,} {removed/n_raw*100:>7.1f}%")
print("─" * 75)
print(f"{'TOTAL APRÈS NETTOYAGE':<45s} {len(df_c):>10,} {n_raw - len(df_c):>10,} {(n_raw-len(df_c))/n_raw*100:>7.1f}%")
print(f"\nTaux de rétention : {len(df_c)/n_raw*100:.1f}%")
```

### Justification des choix

::: {.callout-tip}
## Décisions clés

**Prix null = inactif** : 80,8 % des listings à prix null ont `availability_365 = 0`. Ce sont des annonces retirées ou dormantes, pas des erreurs de saisie. Seulement 1,2 % d'anomalies (prix null mais listing actif).

**Hotel room exclu** : Représente ~1 % de la base. Comportement tarifaire et d'usage très différent (réservation plateforme hôtelière, pas location de logement).

**Prix [10, 1000] EUR** : Borne basse (10€/nuit) exclut les erreurs de saisie. Borne haute (1000€) : au-delà, marché de niche ultra-luxe non représentatif.

**Longterm flaggé, pas exclu** : `minimum_nights ≥ 30` est un **indicateur de régulation** (effet Barcelona, Berlin, Istanbul). Exclure ces listings masquerait un signal structurel majeur.
:::

# Difficultés rencontrées et solutions

::: {.callout-warning}
## Difficultés techniques

### Scraping et données brutes

| Problème | Impact | Solution |
|:---------|:-------|:---------|
| **URLs atypiques** (Irlande, Malte, Nouvelle-Zélande) | sp04 crashait sur format non standard | Normalisation regex dans sp04, skip silencieux si erreur |
| **Paris sept 2025 : prix vide** dans sumlistings | Listings sans prix → exclusion massive | Utiliser listings.gz (74 cols) pour Paris si besoin du snapshot sept |
| **Régions vs villes** (Sicile, Crète, Baléares) | Biais rural dans consolidation | Liste d'exclusion explicite dans sp07 |
| **Snapshots non alignés** | Dates variables selon villes (juin ±2 semaines) | Tolérance : snapshot `25-06` = tout fichier juin 2025 |

### Population et logements

| Problème | Impact | Solution |
|:---------|:-------|:---------|
| **Périmètre commune vs métropole** | Manchester IA = Greater Manchester (2.8M) vs commune (550K) | Documenter, utiliser périmètre IA cohérent |
| **Logements non disponibles** pour 22 villes | Pression logement biaisée | Estimation par ratio national OCDE (logements/1000 hab) |
| **Eurostat Urban Audit** inutilisable | Greater city ≠ commune propre, logements absents | Référentiel maison (city_reference_data.py) |

### Rendu Quarto

| Problème | Impact | Solution |
|:---------|:-------|:---------|
| **Plotly 6 + reticulate** = double affichage | Figures dupliquées, HTML corrompu | Monkey-patch `fig.show()` → `print(to_html())` |
| **Whitespace dans HTML** → pandoc code blocks | Graphiques rendus comme texte brut | `re.sub(r'>\s+<', '><', html).strip()` |
| **JS heap OOM** sur gros rapports | Render crash après 80+ chunks | `NODE_OPTIONS="--max-old-space-size=8192"` |
| **`column: page` + `output: asis`** | Charts débordent du viewport | Utiliser `width=` dans Plotly + CSS overflow |
| **`display()` en knitr** | Crash reticulate (pas de kernel Jupyter) | Remplacer par `print()` |
:::

# Méthodologie ACP

## Variables actives

```{python}
#| label: acp-method-vars

acp_vars = ["listings_1000hab", "entire_1000hsg", "prix_med", "prix_iqr",
            "pct_entire", "pct_multi", "pct_longterm", "ratio_lh",
            "cr_hosts_50pct", "dispo_med", "reviews_med", "rpm_med"]

print(f"ACP sur {len(acp_vars)} variables actives :\n")
print("Variables retenues (ratios et pourcentages normalisés) :")
for v in acp_vars:
    print(f"  • {v}")

print(f"\nVariables exclues (justification) :")
exclusions = [
    ("n_listings, n_entire, n_hosts", "Volumes bruts → effet taille, redondant avec pression"),
    ("pop, housing", "Variables supplémentaires, pas de signal propre"),
    ("prix_moy, prix_q25, prix_q75", "Redondant avec prix_med + prix_iqr"),
    ("dispo_moy", "Très corrélé à dispo_med (r > 0.95)"),
    ("listings_1000hsg", "Très corrélé à entire_1000hsg (r > 0.90)"),
]
for var, reason in exclusions:
    print(f"  ✗ {var}")
    print(f"    → {reason}")
```

## Protocole

1. **Standardisation** : centrage-réduction (z-scores) sur les 12 variables actives
2. **ACP** : décomposition en valeurs propres de la matrice de corrélation
3. **Rétention** : composantes retenues selon règle des 80 % de variance cumulée
4. **Clustering Ward** : distance euclidienne sur les 4 premières composantes
5. **Choix de k** : score silhouette pour k ∈ {3, 4, 5, 6}, retenir le maximum
6. **Profils** : médiane par cluster sur les variables clés

::: {.callout-tip}
## Pourquoi Ward sur composantes et pas sur variables brutes ?

Les variables ont des **échelles très différentes** (pression 0-55, prix 37-223, pct 0-98). La standardisation résout ce problème, mais l'ACP apporte en plus :
- **Décorrélation** : les composantes sont orthogonales → distance euclidienne cohérente
- **Réduction de bruit** : les dernières composantes captent du bruit, pas du signal
- **Interprétabilité** : les clusters se projettent lisiblement sur le biplot
:::

# Sources et limites

::: {.callout-note}
## Sources des données

| Source | Contenu | Dernière mise à jour |
|:-------|:--------|:---------------------|
| [Inside Airbnb](https://insideairbnb.com/) | Listings, prix, disponibilité, reviews | Juin 2025 |
| INSEE RP2022 | Population + logements commune propre (France) | 2022 |
| ONS / GLA | Population Londres + logements | 2023 |
| ISTAT | Population + logements Italie | 2021-2023 |
| INE (Espagne) | Population communes | 2024 |
| Eurostat | Ratios nationaux logements/1000 hab | 2022 |
| BCE | Taux de change EUR | Février 2026 |

## Limites principales

1. **Snapshot unique** (juin 2025) : pas de dimension temporelle, saisonnalité masquée
2. **Population commune propre** : 22/64 villes avec logements estimés (ratio national)
3. **Périmètre géographique variable** : Manchester = metro, Paris = commune
4. **Biais Inside Airbnb** : données scrapées, pas API officielle → listings retirés possibles
5. **Pas de données revenus** : ni taux d'occupation réel, ni revenus hôtes
6. **FX manuels** : taux fixes février 2026, pas d'ajustement dynamique
:::
